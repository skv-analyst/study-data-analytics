Иногда нужно не прогнозировать ряд, а понять, к какому типу он относится: товар сезонный или нет, магазин крупный
или маленький, датчик исправен или сломан. Это классификация рядов: по примерам с известным ответом модель учится
относить новые ряды к одному из двух классов. Задача главы — разобраться, по каким признакам ETNA сравнивает ряды
и как честно проверить, что классификатор работает.

## 1. Теория

### 1.1 Идея

**Ряд превращают в признаки, а дальше работает обычный классификатор.** Сырые значения плохо подходят для
классификации: значений в ряду много, а рядов для обучения обычно мало. Поэтому каждый ряд сначала описывают
небольшим набором чисел — признаками, а уже их отдают привычной модели, например логистической регрессии.

**Два способа получить признаки в ETNA:**

| способ | как описывает ряд | что видит | чего не видит |
|---|---|---|---|
| `TSFreshFeatureExtractor` | библиотека [tsfresh](https://tsfresh.readthedocs.io/): статистики ряда. Минимальный набор — 10 чисел: сумма, среднее, медиана, длина ряда, стандартное отклонение, дисперсия, среднеквадратичное значение, минимум, максимум и максимум по модулю | уровень и размах значений | порядок дней: перемешанный ряд для него тот же |
| `WEASELFeatureExtractor` | алгоритм WEASEL: режет ряд на кусочки, приводит каждый к одному масштабу и считает, какие формы встречаются и как часто — подъём, спад, пик, ровный участок | форму ряда и узоры | уровень и размах: тихий и громкий шум для него одинаковы |

Тот же WEASEL стоит внутри анализатора прогнозируемости из главы [«Анализ прогнозируемости»](13-predictability.md),
только там модель уже обучена разработчиками ETNA. Здесь классификатор обучаем сами — на своих классах.

**Как оценить качество:** кросс-валидацией — ряды делят на фолды, по очереди учатся на всех фолдах, кроме одного, и
проверяют на оставшемся. Основная метрика — {abbr}`AUC (Насколько уверенно модель отделяет класс 1 от класса 0. Возьми наугад ряд класса 1 и ряд класса 0: AUC — доля случаев, когда модель дала ряду класса 1 вероятность выше. 1 — классы разделены без ошибок, 0.5 — угадывание монеткой.)`.
Вторая метрика — доля верных ответов при пороге 0.5.

### 1.2 Параметры и реализация

Классификатор лежит в `etna.experimental` — это экспериментальная часть библиотеки, и для неё нужно расширение
`classification` (`pip install "etna[classification]"`). Ряды он принимает не в `TSDataset`, а списком массивов
numpy — длина рядов может быть разной.

#### Классификатор

```python
class TimeSeriesBinaryClassifier:
    def __init__(
        self, feature_extractor: BaseTimeSeriesFeatureExtractor, classifier: ClassifierMixin, threshold: float = 0.5
    ):
```

- `feature_extractor` — способ получить признаки: `TSFreshFeatureExtractor` или `WEASELFeatureExtractor`;
- `classifier` — любой классификатор с интерфейсом sklearn;
- `threshold` — порог вероятности: выше него ряд относится к классу 1.

| метод | что делает |
|---|---|
| `fit(x, y)` | обучить на списке рядов `x` и метках `y` — только 0 и 1 |
| `predict_proba(x)` | вероятность класса 1 для каждого ряда |
| `predict(x)` | класс 0 или 1 по порогу |
| `masked_crossval_score(x, y, mask)` | кросс-валидация: `mask` — номер фолда для каждого ряда. Возвращает AUC, precision, recall и F1 по фолдам |

#### Способы признаков

```python
TSFreshFeatureExtractor(default_fc_parameters=None, fill_na_value=-100, n_jobs=1, **kwargs)
```

- `default_fc_parameters` — набор статистик tsfresh, по умолчанию минимальный `MinimalFCParameters()`;
- `fill_na_value` — чем заменить статистики, которые не удалось посчитать.

```python
WEASELFeatureExtractor(padding_value, word_size=4, n_bins=4, window_sizes=None, window_steps=None, strategy="entropy", chi2_threshold=2, ...)
```

- `padding_value` — чем дополнить ряд при прогнозе, если он короче самого короткого ряда из обучения; `"back_fill"` —
  первым значением ряда;
- `window_sizes`, `window_steps` — длины кусочков и шаг между ними, в долях длины ряда;
- `word_size`, `n_bins` — насколько подробно описывается форма кусочка;
- `chi2_threshold` — отбор признаков: чем выше, тем меньше форм остаётся.

#### Как применять

```python
clf = TimeSeriesBinaryClassifier(
    feature_extractor=WEASELFeatureExtractor(padding_value="back_fill"),
    classifier=LogisticRegression(max_iter=1000),
)
clf.fit(x_train, y_train)  # x_train — список массивов, y_train — массив из 0 и 1
proba = clf.predict_proba(x_test)
```

### 1.3 Особенности

- **WEASEL капризен к параметрам.** Значения по умолчанию подходят не всегда: на коротких рядах он может упасть с
  ошибкой или дать слабый результат. Параметры окон и разбиения приходится подбирать под свои ряды.
- **Только два класса.** Для трёх и больше классов `TimeSeriesBinaryClassifier` не подходит.

## 2. Практика

### Задание 1. Синтетика: два набора классов

<!-- Тетрадка: ../notebooks/15-classification.ipynb, шаги 1.1–1.2. -->

Два набора по 200 рядов — по 100 каждого класса, 12 недель, уровень ряда случайный от 50 до 200:

- **`pattern`:** класс 1 — недельный узор, выходные выше будней; класс 0 — те же значения, перемешанные по дням.
  Среднее, разброс, минимум и максимум у ряда и его перемешанной копии совпадают точно, разный только порядок дней;
- **`noise`:** шум без узора, класс 0 — тихий (±3% от уровня), класс 1 — громкий (±30%). Форма одна, разный только
  размах.

```{image} img/15-synthetic.png
:alt: Примеры рядов двух классов в наборах pattern и noise
```

В каждом наборе классы мы задали сами, поэтому правильный ответ для каждого ряда известен. Классификатор должен
научиться отличать класс 0 от класса 1. Пробуем два способа признаков — tsfresh и WEASEL, классификатор в обоих
случаях — логистическая регрессия, проверка — кросс-валидация на 5 фолдах.

Как читать результат: AUC около 1 — классификатор разделил классы, около 0.5 — не смог, угадывает наугад.

**Вопрос:** какой способ признаков разделит классы в наборе `pattern`, а какой — в наборе `noise`?

:::{dropdown} Ответ
| набор | чем различаются классы | AUC `tsfresh` | AUC `weasel` |
|---|---|---|---|
| `pattern` — узор против перемешанного | только порядком дней | 0.42 — не разделил | **1.00 — разделил** |
| `noise` — тихий шум против громкого | только размахом | **1.00 — разделил** | 0.51 — не разделил |

- **Каждый способ разделил классы в одном наборе и не смог в другом** — потому что наборы устроены противоположно.
- **`pattern`: справился WEASEL.** Классы отличаются только порядком дней, а tsfresh считает среднее, разброс,
  минимум и максимум — у перемешанного ряда они те же, что у исходного. Для tsfresh классы одинаковые, и его AUC 0.42 —
  то же угадывание монеткой. WEASEL смотрит на форму и видит недельный узор.
- **`noise`: справился tsfresh.** Классы отличаются только размахом, и разброс у tsfresh сразу его показывает.
  WEASEL приводит каждый кусочек ряда к одному масштабу — тихий и громкий шум для него одной формы.
- **Вывод:** способ признаков выбирают по тому, чем различаются классы: формой или величиной. Если не знаешь —
  пробуй оба.
:::

### Задание 2. Окна реальных магазинов

<!-- Тетрадка: ../notebooks/15-classification.ipynb, шаги 2.1–2.2. -->

Те же 10 магазинов, что в главе [«Кластеризация временных рядов»](14-clustering.md), по 2 каждого размера, 5 месяцев
с апреля по август. Рядов слишком мало для обучения, поэтому каждый нарезан на окна по 4 недели с шагом в неделю —
по 18 окон на магазин. Задача — по одному окну понять, крупный магазин или маленький:

- класс 1 — крупный (`7–10`, `10+`), класс 0 — маленький (`<3`, `3–5`);
- средние `5–7` не берём, чтобы классы не пересекались.

**Как проверяем.** Классификатор учим на окнах 6 магазинов — 3 крупных и 3 маленьких, а проверяем на окнах 2
оставшихся, которых он ни разу не видел. Повторяем 4 раза, чтобы каждый магазин побывал в проверке. Если бы окна
одного магазина попадали и в обучение, и в проверку, классификатор мог бы запомнить сам магазин — его уровень и
привычные скачки — и отвечать правильно, вообще не разбираясь в размерах.

**Три способа признаков:**

1. **tsfresh по окну как есть.** Видит уровень: сколько заказов в день у магазина.
2. **tsfresh по окну в долях от его среднего.** Каждое значение окна делим на среднее этого окна: 1.2 — день на 20%
   выше обычного для этого окна, 0.8 — на 20% ниже. Уровень пропадает: окно маленького и крупного магазина
   становятся одного масштаба (правый график ниже). Остаются недельный узор и относительный размах скачков. Этот
   способ отвечает на вопрос: отличаются ли магазины чем-то, кроме объёма?
3. **WEASEL.** Видит только форму, уровень он убирает сам.

```{image} img/15-windows.png
:alt: Окна четырёх магазинов разного размера — как есть и в долях от своего среднего
```

**Вопрос:** получится ли узнать размер магазина по окну? А по одной форме, без уровня?

:::{dropdown} Ответ
| способ | что видит | AUC | доля верных |
|---|---|---|---|
| `tsfresh` | уровень и размах | **1.00** | **1.00** |
| `tsfresh` в долях от среднего | относительный размах, без уровня | 0.67 | 0.58 |
| `weasel` | только форму | 0.59 | 0.57 |

- **По окну как есть размер угадывается безошибочно:** размер магазина — это и есть объём заказов, а tsfresh видит
  среднее.
- **По форме — почти наугад:** без уровня AUC 0.59–0.67, доля верных ответов 0.57–0.58 при 0.5 у монетки.
  Ни один магазин не узнаётся по форме уверенно: средняя вероятность «крупный» по его окнам — от 0.25 до 0.70, без
  связи с размером.
- **Почему форма не помогает:** недельный узор у магазинов всех размеров одинаковый — пики в пятницу и субботу.
  Маленький и крупный магазин отличаются только тем, сколько у них заказов.
- **К тому же выводу мы пришли в главе [«Кластеризация временных рядов»](14-clustering.md):** после нормировки
  кластеры там тоже не совпали с размерами магазинов. Два разных инструмента — кластеризация без разметки и
  классификатор с разметкой — показали одно и то же.
:::

## 3. Итоги

- **`TimeSeriesBinaryClassifier` = способ признаков + обычный классификатор sklearn.** tsfresh видит величину значений,
  WEASEL — форму. Выбирай по тому, чем различаются классы, или пробуй оба.
- **Размер магазина классификатор узнаёт по объёму заказов, а по форме — нет:** недельный узор у магазинов всех
  размеров одинаковый.
