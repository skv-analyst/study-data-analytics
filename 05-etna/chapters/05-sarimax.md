`SARIMAX` — более сложная модель по сравнению с наивными и скользящими средними. Она не использует одну
фиксированную формулу усреднения прошлых значений, а оценивает параметры статистической модели по данным.

В этой главе разберём, как устроены несезонная и сезонная части `(p, d, q)` и `(P, D, Q, s)`, зачем нужно
дифференцирование, как по ACF/PACF подобрать параметры вручную и чем ручной подбор отличается от
автоматического. Практика проводится на двух юнитах размера `10+`.

Исполняемый код и полные результаты экспериментов — в
[исходном ноутбуке](../notebooks/05-sarimax.ipynb).

## 1. Теория

### 1.1 Идея SARIMAX

**SARIMAX** расшифровывается как *Seasonal AutoRegressive Integrated Moving Average with eXogenous factors*.
Модель записывается в виде:

\[
SARIMAX(p,d,q)(P,D,Q,s).
\]

У неё две части, которые описывают разные источники зависимости во временном ряду:

- **Несезонная часть `(p, d, q)`** — зависимости между соседними точками во времени. Например, помогает
  ответить на вопрос: если вчера было много заказов, поможет ли это предсказать сегодняшний уровень?
- **Сезонная часть `(P, D, Q, s)`** — зависимости между точками одного и того же положения в цикле. Например,
  помогает учесть, что пятница может быть похожа на прошлую пятницу, а не на четверг.

Параметры несезонной части:

| Параметр | Название | Смысл |
|---|---|---|
| `p` | AR (*AutoRegressive*) | Порядок авторегрессии: сколько прошлых значений ряда участвует в прогнозе. |
| `d` | I (*Integrated*) | Сколько раз применяется обычное дифференцирование, чтобы убрать тренд и добиться стационарности. |
| `q` | MA (*Moving Average*) | Порядок скользящего среднего ошибок: учитывает, насколько модель ошибалась на предыдущих шагах. |

Параметры сезонной части:

| Параметр | Название | Смысл |
|---|---|---|
| `P` | Seasonal AR | Авторегрессия по точкам, отстоящим на полный сезонный цикл. |
| `D` | Seasonal I | Сколько раз применяется сезонное дифференцирование. |
| `Q` | Seasonal MA | Поправка на ошибки в соответствующих точках предыдущих сезонных циклов. |
| `s` | Season length | Длина полного сезонного цикла: например, `7` для недельной сезонности дневных данных или `12` для годовой сезонности месячных данных. |

В отличие от `NaiveModel`, `MovingAverageModel` и `SeasonalMovingAverageModel`, у SARIMAX нет единой формулы
вида «прогноз = среднее нескольких прошлых значений». Модель **оценивает числовые параметры по данным** —
в реализации используется метод максимального правдоподобия (*Maximum Likelihood Estimation*, MLE).

Буква `I` означает *Integrated* — интегрирование через дифференцирование. Модель может сама преобразовывать
ряд внутри обучения и прогноза в соответствии с `d` и `D`. Поэтому исходный `TSDataset` не нужно заранее
дифференцировать и передавать модели в таком виде.

Буква `X` означает возможность учитывать экзогенные факторы — дополнительные признаки, которые могут
помогать объяснять целевую переменную. В этой главе экзогенные регрессоры не используются.

### 1.2 Параметры и реализация

В ETNA используется класс `SARIMAXModel` из `etna/models/sarimax.py`. Его сигнатура в сокращённом виде:

```python
class SARIMAXModel(PerSegmentModelMixin, ...):
    def __init__(
        self,
        order=(1, 0, 0),
        seasonal_order=(0, 0, 0, 0),
        trend=None,
        ...
    ):
```

Основные параметры:

| Параметр | Значение |
|---|---|
| `order` | Кортеж `(p, d, q)`. По умолчанию `(1, 0, 0)`. |
| `seasonal_order` | Кортеж `(P, D, Q, s)`. По умолчанию `(0, 0, 0, 0)`, то есть сезонная часть выключена. |
| `trend` | Детерминированный тренд: `'c'` — константа, `'t'` — линейный тренд по времени, `'ct'` — оба компонента. По умолчанию `None`. |

**Что важно в реализации ETNA:**

- У модели нет прежних `window`, `seasonality` и `context_size`: вместо готовой формулы усреднения происходит
  полноценное обучение.
- `fit()` выполняет MLE-оптимизацию параметров. Это реальное вычислительно затратное обучение, а не простая
  подготовка объекта.
- Благодаря `PerSegmentModelMixin` модель обучается **отдельно для каждого сегмента**: под капотом для каждого
  юнита создаётся своя независимая модель.
- Вызов прогноза проще, чем у предыдущих моделей: не нужно явно передавать `tail_steps` и `prediction_size`.
  Модель хранит необходимое внутреннее состояние.

Типичный порядок обучения и прогноза:

```python
from etna.models import SARIMAXModel

HORIZON = 14

model = SARIMAXModel(
    order=(1, 0, 0),
    seasonal_order=(0, 1, 1, 7),
)

model.fit(train_ts)

future_ts = train_ts.make_future(future_steps=HORIZON)
forecast_ts = model.forecast(future_ts)
```

### 1.3 Дифференцирование и стационарность

Дифференцирование — это вычитание текущего значения из предыдущего. Вместо исходного уровня ряда мы
рассматриваем его изменения.

**Обычное дифференцирование первого порядка:**

\[
\Delta y_t = y_t - y_{t-1}.
\]

Оно сравнивает значение с предыдущей точкой и помогает убрать тренд.

**Сезонное дифференцирование с периодом `s`:**

\[
\Delta_s y_t = y_t - y_{t-s}.
\]

Оно сравнивает значение с той же точкой предыдущего цикла. Например, при `s=7` понедельник сравнивается с
предыдущим понедельником. Это помогает убрать недельную сезонность.

Параметры `d` и `D` показывают, сколько раз применяются соответствующие операции:

- `d=1` — одно обычное дифференцирование;
- `D=1` — одно сезонное дифференцирование;
- `d=0`, `D=1` — обычное дифференцирование не требуется, достаточно сезонного.

**Как проверить стационарность?** В ноутбуке используется тест Дики-Фуллера (`adfuller`):

- нулевая гипотеза `H₀`: ряд нестационарен, в нём присутствует единичный корень;
- альтернативная гипотеза `H₁`: ряд стационарен;
- если `p-value < 0.05`, нулевую гипотезу можно отклонить;
- если `p-value ≥ 0.05`, нет достаточных оснований отклонить гипотезу о нестационарности.

**Кто дифференцирует, а кто выбирает параметры?**

1. На отдельной копии ряда мы проводим диагностику: проверяем стационарность, применяем `.diff(periods=s)`
   и при необходимости `.diff(1)`.
2. По результатам диагностики выбираем `d`, `D` и `s`.
3. По ACF/PACF подбираем кандидатов для `p`, `q`, `P`, `Q`.
4. В `SARIMAXModel.fit()` передаём **оригинальный, недифференцированный ряд**. Модель сама выполнит
   необходимое дифференцирование согласно выбранным `d` и `D`.

Не нужно передавать модели вручную продифференцированный ряд: иначе дифференцирование может быть применено
повторно.

**Не переусердствуй с дифференцированием.** Если ряд стал стационарным после сезонного `diff(s)`, дополнительный
`diff(1)` может быть не нужен. Это проверим в первом задании.

### 1.4 Как читать ACF и PACF

Для подбора параметров используются две функции:

- **ACF** (*Autocorrelation Function*) показывает корреляцию ряда с его прошлыми значениями на разных лагах.
- **PACF** (*Partial Autocorrelation Function*) показывает связь с конкретным лагом после учёта промежуточных
  лагов.

В качестве практической шпаргалки:

| График | Первые лаги | Сезонные лаги, кратные `s` |
|---|---|---|
| ACF | Кандидат для `q` | Кандидат для `Q` |
| PACF | Кандидат для `p` | Кандидат для `P` |

Это не механическое правило: ACF/PACF помогают сформировать кандидатов, а окончательный выбор проверяется
по качеству прогноза на отложенном периоде.

**Пошаговый алгоритм подбора `(p, d, q), (P, D, Q, s)`:**

1. **Найди `s`.** На сыром ряде посмотри ACF. Повторяющиеся пики на лагах `7`, `14`, `21` и т. д. могут
   указывать на недельную сезонность. На этом шаге стационарность не обязательна.
2. **Определи `D` и `d`.** На отдельной копии ряда проверь ADF. Если ряд нестационарен, попробуй сезонное
   дифференцирование `.diff(periods=s)` и снова проверь ADF. Если ряд всё ещё нестационарен, попробуй
   `.diff(1)`. Если сезонного дифференцирования достаточно, `d=0`.
3. **Построй ACF и PACF на стационарном ряде.** Первые лаги помогают выбрать `q` и `p`, сезонные лаги —
   `Q` и `P`.
4. **Собери кандидатов:** `order=(p, d, q)` и `seasonal_order=(P, D, Q, s)`.
5. **Обучи SARIMAX на исходном `train_ts`.** Не передавай в модель диагностическую продифференцированную копию.


## 2. Практика 

### Задание 1. Синтетика: делаем ряд стационарным дифференцированием

Сначала создадим синтетический ряд, в котором одновременно есть линейный тренд, недельная сезонность и
небольшой шум. Это позволит увидеть, как сезонное и обычное дифференцирование меняют структуру данных.

Шум нужен в том числе для того, чтобы после дифференцирования ряд не выродился в константу: в таком случае
`adfuller` может отказаться считать тест.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

from statsmodels.tsa.stattools import adfuller
from statsmodels.graphics.tsaplots import plot_acf, plot_pacf

np.random.seed(0)
periods = 70

day_of_week_pattern = np.array([10, 20, 15, 25, 30, 50, 60], dtype=float)
seasonal = np.tile(day_of_week_pattern, periods // 7 + 1)[:periods]
trend = np.arange(periods) * 1.5
noise = np.random.normal(0, 3, periods)

series = pd.Series(
    seasonal + trend + 100 + noise,
    index=pd.date_range("2024-01-01", periods=periods, freq="D"),
)

series.plot(title="Синтетика: тренд + недельная сезонность + шум");
```

```{image} img/05-sarimax-synthetic-raw.png
:alt: Синтетический ряд с линейным трендом, недельной сезонностью и шумом
```

Для проверки стационарности используем небольшую функцию:

```python
def get_stattest(series, alpha=0.05):
    result = adfuller(series)
    p_value = result[1]

    print(f"p-value: {p_value:.8f}")

    if p_value < alpha:
        print("Отклоняем H0: есть основания считать ряд стационарным")
    else:
        print("Не можем отклонить H0 о нестационарности ряда")
```

Проверим исходный ряд:

```python
get_stattest(series)
```

Результат:

```text
p-value: 0.98392682
Не можем отклонить H0 о нестационарности ряда
```

Теперь уберём недельную сезонность сезонным дифференцированием с шагом `7`:

```python
series_diff_seasonal = series.diff(periods=7).dropna()

series_diff_seasonal.plot(
    marker="o",
    title="После сезонного diff(periods=7)",
);

get_stattest(series_diff_seasonal)
```

```{image} img/05-sarimax-synthetic-seasonal-diff.png
:alt: Синтетический ряд после сезонного дифференцирования с периодом 7
```

```text
p-value: 0.00001270
Можем отклонить H0 о нестационарности ряда
```

После сезонного дифференцирования ряд уже проходит тест стационарности. Проверим, изменится ли что-нибудь,
если дополнительно применить обычное дифференцирование первого порядка:

```python
series_diff_seasonal_diff1 = series_diff_seasonal.diff(1).dropna()

series_diff_seasonal_diff1.plot(
    marker="o",
    title="После diff(periods=7) + diff(1)",
);

get_stattest(series_diff_seasonal_diff1)
```

```{image} img/05-sarimax-synthetic-seasonal-and-first-diff.png

```

```text
p-value: 0.00004822
Можем отклонить H0 о нестационарности ряда
```

Сводка эксперимента:

| Состояние ряда | ADF `p-value` | Вывод при `alpha=0.05` |
|---|---:|---|
| Исходный ряд | 0.98392682 | Не можем отклонить H₀ |
| После `diff(7)` | 0.00001270 | Отклоняем H₀ |
| После `diff(7)` и `diff(1)` | 0.00004822 | Отклоняем H₀ |

**Вопрос:** зачем добавлять обычное `diff(1)`, если после сезонного `diff(7)` ряд уже стал стационарным?

:::{dropdown} Ответ
В этом эксперименте дополнительное `diff(1)` не требуется. После сезонного дифференцирования `p-value` уже
меньше `0.05`, поэтому нулевая гипотеза о нестационарности отклоняется.

После второго дифференцирования ряд тоже проходит тест, но сам по себе меньший или больший `p-value` не
является оценкой качества будущего прогноза. Практический вывод здесь проще: если сезонного дифференцирования
уже достаточно, не нужно автоматически добавлять ещё один шаг.
:::

По графикам формируем два кандидата. Они по-разному интерпретируют корреляцию на первом и сезонном лагах.

**Кандидат 1 — AR(1) + сезонный MA(1):**

```python
order = (1, 0, 0)
seasonal_order = (0, 1, 1, 7)
```

- `p=1`: на PACF после `diff(7)` значим лаг 1 (примерно `0.25`), дальше наблюдается обрыв.
- `d=0`: после сезонного дифференцирования ряд уже стационарен.
- `q=0`: корреляцию на первом лаге объясняем через AR(1).
- `P=0`: сезонные лаги на PACF плавно затухают.
- `D=1`: достаточно одного сезонного дифференцирования.
- `Q=1`: на ACF сильный пик на лаге 7 (примерно `−0.47`), а на лаге 14 значение уже в пределах шума.
- `s=7`: недельный цикл.

**Кандидат 2 — MA(1) + сезонный AR(1):**

```python
order = (0, 0, 1)
seasonal_order = (1, 1, 0, 7)
```

Это альтернативная интерпретация тех же графиков:

- `q=1`: связь на первом лаге объясняем через MA(1), а не AR(1);
- `P=1`: на PACF значим сезонный лаг 7 (примерно `−0.45`), поэтому пробуем сезонный AR(1);
- `D=1`, `d=0`, `s=7` остаются такими же.

Оба варианта — кандидаты, а не окончательный ответ. Их качество сравним на отложенном периоде.

**Вопрос:** почему после `diff(7)` мы передаём в `SARIMAXModel` параметры `d=0`, `D=1`, но саму модель обучаем на исходном `train_ts`?

:::{dropdown} Ответ
Копия ряда после дифференцирования нужна только для диагностики: на ней мы проверяем стационарность и изучаем ACF/PACF.
По результатам диагностики выбираем параметры `d` и `D`.

Внутри `SARIMAXModel` дифференцирование выполняется самой моделью. Поэтому в `fit()` передаётся исходный
`train_ts`, а не `train_series_diff`. Если передать уже продифференцированный ряд и одновременно указать
`D=1`, модель применит сезонное дифференцирование повторно.
:::

### Задание 5. Сравниваем подходы на двух юнитах

Теперь обучим модели сразу на двух сегментах. Сравним три подхода:

1. **Baseline** — настройки SARIMAX по умолчанию, без сезонной части.
2. **Одна ручная конфигурация** — два варианта, параметры которых подобраны на `70650540` и затем применяются
   к обоим юнитам.
3. **Автоподбор** — отдельные порядки для каждого юнита с помощью `AutoARIMAModel` и
   `StatsForecastAutoARIMAModel`.

Разбиение одинаковое для всех моделей:

- train: `2026-04-01`…`2026-08-17`, 139 дней;
- test: `2026-08-18`…`2026-08-31`, 14 дней.

```python
from etna.models import (
    SARIMAXModel,
    AutoARIMAModel,
    StatsForecastAutoARIMAModel,
)

train_sample_ts, test_sample_ts = orders_sample_ts.train_test_split(
    test_size=HORIZON,
)

models = {
    # 1. Baseline: дефолтный SARIMAX без сезонности
    "sarimax_default": SARIMAXModel(),

    # 2. Одна ручная конфигурация для обоих сегментов
    "sarimax_first": SARIMAXModel(**MODEL_PARAMS["first"]),
    "sarimax_second": SARIMAXModel(**MODEL_PARAMS["second"]),

    # 3. Автоподбор параметров отдельно для каждого сегмента
    "auto_arima_pmdarima": AutoARIMAModel(m=7, seasonal=True),
    "auto_arima_statsforecast": StatsForecastAutoARIMAModel(
        season_length=7,
    ),
}
```

Автоматические алгоритмы сами подбирают порядки модели, но длину сезонного цикла `7` мы задаём явно. В ноутбуке для выбора `d`/`D` используются статистические тесты, а `p`/`q`/`P`/`Q` подбираются пошаговым перебором по AIC.

Обучим кандидатов и посчитаем SMAPE отдельно по сегментам и в режиме `macro`:

```python
forecasts = {}
rows = []

for name, model in models.items():
    model.fit(train_sample_ts)

    forecast_ts = model.forecast(
        train_sample_ts.make_future(future_steps=HORIZON)
    )
    forecasts[name] = forecast_ts

    smape_per_segment = SMAPE(mode="per-segment")(
        y_true=test_sample_ts,
        y_pred=forecast_ts,
    )
    smape_macro = SMAPE(mode="macro")(
        y_true=test_sample_ts,
        y_pred=forecast_ts,
    )

    rows.append({
        "model": name,
        **{f"smape_{segment}": value for segment, value in smape_per_segment.items()},
        "smape_macro": smape_macro,
    })

smape_df = pd.DataFrame(rows).set_index("model").round(2)
smape_df.sort_values("smape_macro")
```

| Одна конфигурация | `sarimax_first` | 11.23 | 6.17 | 8.70 |
| Одна конфигурация | `sarimax_second` | 9.22 | **5.63** | **7.42** |
| Автоподбор | `auto_arima_pmdarima` | 14.46 | 6.65 | 10.55 |

связывается с тем, что pmdarima определяет сезонное дифференцирование другим тестом (OCSB), а на коротком
ряде диагностические тесты могут расходиться.

Одинаковое значение `m=7` или `season_length=7` задаёт длину сезонного цикла, но не заставляет алгоритмы

## 3. Итоги

- **SARIMAX сочетает несезонную и сезонную части.** `order=(p,d,q)` описывает зависимости между соседними
  точками, а `seasonal_order=(P,D,Q,s)` — зависимости между точками одного сезонного цикла.
- **`d` и `D` отвечают за дифференцирование.** Обычное дифференцирование помогает убрать тренд, сезонное —
  повторяющийся цикл.
- **Диагностику и обучение нужно разделять.** ADF, ACF и PACF изучаем на отдельной копии ряда, но в
  `SARIMAXModel.fit()` передаём исходный ряд. Модель сама применяет дифференцирование по `d` и `D`.
- **На выбранном юните сезонного дифференцирования оказалось достаточно.** Для `70650540` исходный ADF
  дал `p-value=0.4312`, после `diff(7)` — `p-value=6.77e-7`; поэтому выбрали `d=0`, `D=1`, `s=7`.
- **Ручной подбор дал лучший результат в этом эксперименте.** Конфигурация `(0,0,1)(1,1,0,7)` получила
  `SMAPE macro=7.42` на двух сегментах.
- **Автоподбор не гарантирует лучший результат.** StatsForecast воспроизвёл первый ручной кандидат, а
  pmdarima выбрал другие порядки и показал большую ошибку.
- **Сезонная часть критически важна для этих рядов.** Baseline без сезонности получил `SMAPE macro=36.12`,
  тогда как модели с сезонной частью — от `7.42` до `10.55`.
- **Небольшой выигрыш над SeasonalMovingAverageModel требует проверки.** Разница `7.42` против `7.55`
  получена на одном 14-дневном тестовом окне. Для надёжного вывода нужен backtest на нескольких окнах.
