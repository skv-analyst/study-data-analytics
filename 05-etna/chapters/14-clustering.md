Кластеризация собирает похожие ряды в группы, не зная заранее, какие группы должны получиться. Это нужно, чтобы
обучать одну модель на группу похожих рядов, проверить свою сегментацию («правда ли магазины одного размера ведут себя
одинаково?») или найти ряды, которые ни на кого не похожи. Задача главы — понять, как ETNA кластеризует ряды и от чего
зависит, какие группы получатся.

## 1. Теория

### 1.1 Идея

**Два шага:**

1. **посчитать расстояния** — для каждой пары рядов одно число: насколько они непохожи;
2. **собрать группы** по этим расстояниям.

**Как собираются группы — иерархическая кластеризация.** Сначала каждый ряд — отдельный кластер. Потом два самых
близких кластера объединяются, и так раз за разом, пока не останется заданное число кластеров. Расстояние между
кластерами из нескольких рядов считается по правилу `linkage` — например, среднее расстояние между их рядами.

**Расстояний в ETNA два:**

| расстояние | как считается | что считает похожим |
|---|---|---|
| евклидово | разницы значений в один и тот же день, возведённые в квадрат и сложенные | ряды, которые в одни и те же дни принимают близкие значения |
| DTW (dynamic time warping, динамическая трансформация времени) | ряды можно растягивать и сдвигать во времени, чтобы похожие куски совпали; расстояние — разница после лучшего совмещения | ряды одной формы, даже если узор у них сдвинут или растянут |

**Что получится, решает подготовка рядов.** Расстояние смотрит на значения, поэтому ряды разного масштаба
группируются по масштабу: магазин на 50 заказов и магазин на 200 далеки всегда. Если важна форма, ряды сначала
приводят к одному масштабу — например, `StandardScalerTransform`: среднее 0, разброс 1 у каждого ряда.

**Центроид** — «средний ряд» кластера, его типичная форма. По центроидам удобно описать кластеры словами.

### 1.2 Параметры и реализация

Оба класса наследуют `HierarchicalClustering` (исходники `etna/clustering/`) и отличаются только расстоянием.
Параметров у конструкторов нет:

```python
class EuclideanClustering(HierarchicalClustering):
    def __init__(self):
        super().__init__(distance=EuclideanDistance())

class DTWClustering(HierarchicalClustering):
    def __init__(self):
        super().__init__(distance=DTWDistance())
```

Всё настраивается методами, их вызывают по порядку:

| метод | что делает |
|---|---|
| `build_distance_matrix(ts)` | считает расстояния между всеми парами рядов |
| `build_clustering_algo(n_clusters=30, linkage="average")` | настраивает сборку групп: `AgglomerativeClustering` из sklearn. `n_clusters` — сколько кластеров нужно, `linkage` — как считать расстояние между кластерами |
| `fit_predict()` | собирает кластеры, возвращает словарь `{сегмент: номер кластера}` |
| `get_centroids()` | центроиды кластеров: для евклидова расстояния — среднее рядов по дням, для DTW — среднее после совмещения рядов |

**Правила `linkage`:**

| правило | расстояние между кластерами |
|---|---|
| `"average"` (по умолчанию) | среднее расстояние между рядами двух кластеров |
| `"complete"` | самое большое расстояние между их рядами |
| `"single"` | самое маленькое расстояние между их рядами |

**Как применять:**

```python
model = EuclideanClustering()
model.build_distance_matrix(ts)
model.build_clustering_algo(n_clusters=3, linkage="average")
segment2cluster = model.fit_predict()

centroids = model.get_centroids()
plot_clusters(ts, segment2cluster, centroids)  # ряды каждого кластера и его центроид
```

### 1.3 Особенности

- **Число кластеров задаёшь сам.** По умолчанию `n_clusters=30` — для десятка рядов это ошибка, задавай всегда.
- **Номер кластера — просто метка.** Кластер 0 не «лучше» кластера 2, а при другом запуске номера могут поменяться.
- **Без нормировки — группы по объёму, с нормировкой — по форме.** Это два разных вопроса к данным, и оба могут быть
  полезны.
- **DTW не видит сдвигов во времени.** Пик в среду и пик в четверг для него одна форма. Если важен день недели, бери
  евклидово расстояние.
- **DTW медленнее.** Каждую пару рядов он совмещает заново, и время растёт с квадратом длины ряда. На сотнях длинных
  рядов это заметно.
- **Пропуски выбрасываются** — с предупреждением, но без заполнения. Лучше заполнить их заранее (глава
  [«Импутация пропусков»](10-imputation.md)) или взять период, где данные есть у всех рядов.
- **`"average"` любит одиночек:** ряд, непохожий на остальных, часто остаётся отдельным кластером. Это не ошибка, а
  подсказка: на такой ряд стоит посмотреть отдельно.

  разные дни. Для недельного узора, где важен именно день, бери евклидово расстояние.

## 3. Итоги

- **Сначала реши, по чему группировать:** ряды как есть группируются по объёму, нормированные — по форме.
- **Евклидово расстояние или DTW:** евклидово различает, в какой день пик, DTW сравнивает только форму и сдвигов во
  времени не видит.
- **Одиночки — тоже результат:** это ряды, на которые стоит посмотреть отдельно.
