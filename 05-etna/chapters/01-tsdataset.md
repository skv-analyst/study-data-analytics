Прежде чем строить прогноз, нужно договориться, **что именно является временным рядом**: какая у него частота, где лежат
даты, сколько рядов прогнозируем и какие признаки доступны. В ETNA за это отвечает `TSDataset` — единая оболочка над
временными рядами. Она приводит данные к общему формату и даёт моделям, трансформам и визуализациям одинаковый
интерфейс.

В главе — как создать данные для экспериментов, перейти между `long` и `wide`, работать с иерархией рядов и
выравнивать сегменты, у которых история заканчивается в разные даты. Исполняемый код и подробные выводы — в
[исходном ноутбуке](../notebooks/01-tsdataset.ipynb).

## 1. Теория

### 1.1 `TSDataset`: время, сегменты и признаки

**Сегмент** — отдельный временной ряд: например, один ресторан, товар или город. **`target`** — величина, которую
хотим прогнозировать. **`timestamp`** — момент наблюдения, **`freq`** — шаг временной сетки (`"D"` для дней, `"h"`
для часов и т. п.). Один `TSDataset` может содержать сразу много сегментов и несколько признаков на сегмент.

**На входе удобно иметь `long`-формат:** каждая строка — наблюдение определённого сегмента в определённый момент.

| timestamp | segment | target |
|---|---|---:|
| 2026-09-01 | segment_0 | 69.483571 |
| 2026-09-02 | segment_0 | 66.308678 |
| 2026-09-01 | segment_1 | 59.923146 |
| 2026-09-02 | segment_1 | 64.896773 |

**Внутри ETNA используется `wide`-представление:** строки — даты, колонки — пары `(segment, feature)` в
`pandas.MultiIndex`. Те же данные выглядят так:

| timestamp | segment_0 / target | segment_1 / target |
|---|---:|---:|
| 2026-09-01 | 69.483571 | 59.923146 |
| 2026-09-02 | 66.308678 | 64.896773 |

```python
from etna.datasets import TSDataset

df_wide = TSDataset.to_dataset(df_long)  # long → wide DataFrame
ts = TSDataset(df_long, freq="D")       # создать объект ETNA из long

df_again = ts.to_pandas(flatten=True)    # TSDataset → long DataFrame
df_internal = ts.to_pandas()             # TSDataset → wide DataFrame
```

Обратную конвертацию самого `DataFrame` делает `TSDataset.to_flatten(df_wide)`; узнать формат —
`DataFrameFormat.determine(df)`. **`long` и `wide` — это формы таблицы, а `TSDataset` — объект с дополнительной
семантикой времени и сегментов.**

`freq` нужен не только для красивого индекса. Он задаёт шаг для построения временной сетки, будущих дат и признаков.
Если в исходных данных нет наблюдения на какую-то дату, после приведения к единой сетке оно может оказаться `NaN`.
Это **не то же самое, что нулевой спрос**: отсутствующее наблюдение нельзя бездумно трактовать как ноль.

### 1.2 Генераторы синтетических данных

Синтетика полезна, когда нужно проверить метод на ряде с известными свойствами и отделить поведение модели от
неожиданностей реальных данных. ETNA предлагает несколько генераторов:

| функция | какой ряд создаёт | когда использовать |
|---|---|---|
| `generate_const_df` | постоянный уровень, при необходимости с шумом | проверить поведение без тренда и сезонности |
| `generate_periodic_df` | повторяющийся периодический рисунок | проверять работу с сезонностью |
| `generate_ar_df` | авторегрессионный ряд: текущее значение зависит от прошлых | проверять модели на данных с инерцией |
| `generate_from_patterns_df` | повторяет явно заданные шаблоны значений | воспроизвести конкретный недельный сценарий |
| `generate_hierarchical_df` | ряды с несколькими уровнями группировки | экспериментировать с иерархиями |

**Общие параметры** из ноутбука:

```python
PARAMS = {
    "periods": 100,
    "start_time": "2026-09-01",
    "scale": 67,
    "n_segments": 2,
    "freq": "D",
    "add_noise": True,
    "sigma": 5,
    "random_seed": 42,
}
```

- `periods` — сколько временных точек в каждом сегменте; при 100 датах и 2 сегментах `long`-таблица содержит 200 строк.
- `start_time` и `freq` — откуда и с каким шагом идут даты.
- `scale` — параметр масштаба генерации; его точный смысл зависит от генератора.
- `add_noise`, `sigma` — добавлять ли случайный шум и какой у него масштаб.
- `random_seed` — позволяет воспроизводить результаты эксперимента.

**`generate_const_df`: постоянный уровень не означает прямую линию.** Если `add_noise=True`, каждое наблюдение
случайно отклоняется от уровня. В ноутбуке уровень 67, а шум имеет `sigma=5`:

```{image} img/01-const.png
:alt: Два ряда вокруг постоянного уровня 67 с добавленным шумом
```

**`generate_from_patterns_df`: узор задаём сами.** В ноутбуке для двух сегментов выбраны шаблоны длиной семь:

```python
patterns = [
    [3, 3, 3, 3, 3, 30, 3],
    [5, 5, 5, 5, 5, 50, 5],
]
```

Поскольку начальная дата — вторник 1 сентября 2026 года, шестой элемент каждого шаблона приходится на воскресенье.
Получаем недельные пики разной силы, поверх которых добавлен шум:

```{image} img/01-patterns.png
:alt: Два синтетических ряда с повторяющимися недельными пиками
```

**`generate_ar_df`: память о прошлом.** Для AR(1) идея описывается уравнением

\[
x_t = \varphi x_{t-1} + \varepsilon_t.
\]

`ar_coef=[0.2]` в ноутбуке означает слабую зависимость от прошлого; коэффициент близкий к единице даёт более
долгую память. При `ar_coef=[0]` зависимость от предыдущего значения исчезает: остаётся шум. В `ar_coef` можно
передать несколько коэффициентов для AR-процесса более высокого порядка.

**`generate_hierarchical_df`: несколько связанных уровней.** В примере `n_segments=[2, 4]` задаёт два сегмента
верхнего уровня и четыре нижнего. Удобно, чтобы проверять согласованность прогнозов «детали ↔ сумма».

### 1.3 Что умеет `TSDataset`

У `TSDataset` много методов, но запоминать каждый по отдельности не нужно. Полезнее разделить API по задачам.

**Атрибуты — что мы знаем о датасете:**

| группа | атрибуты | смысл |
|---|---|---|
| Сегменты и время | `segments`, `freq`, `freq_offset`, `timestamps` | какие ряды есть, каков шаг и диапазон времени |
| Признаки | `features`, `regressors`, `known_future` | какие колонки доступны и какие внешние признаки известны в будущем |
| Результаты модели | `target_components_names`, `prediction_intervals_names` | имена компонент `target` и границ интервала прогноза, если они добавлены |
| Иерархия | `current_df_level`, `current_df_exog_level` | на каких уровнях иерархии находятся основные и внешние данные |

**Методы — что можно сделать с датасетом:**

| задача | методы |
|---|---|
| Формат и создание | `to_dataset`, `to_flatten`, `to_pandas`, `create_from_misaligned` |
| Осмотреть | `head`, `tail`, `describe`, `info`, `isnull`, `plot`, `size` |
| Разделить и продолжить время | `train_test_split`, `make_future`, `tsdataset_idx_slice` |
| Изменить признаки | `add_features_from_pandas`, `update_features_from_pandas`, `drop_features` |
| Применить трансформы | `fit_transform`, `transform`, `inverse_transform` |
| Работать с иерархией | `has_hierarchy`, `level_names`, `get_level_dataset`, `to_hierarchical_dataset` |
| Компоненты цели | `add_target_components`, `get_target_components`, `drop_target_components` |
| Интервалы прогноза | `add_prediction_intervals`, `get_prediction_intervals`, `drop_prediction_intervals` |
| PyTorch | `to_torch_dataset` |

Особенно важны три операции, которые будут встречаться дальше в книге:

- **`train_test_split`** — выделяет обучение и проверку по времени. В прогнозировании нельзя случайно перемешать
  наблюдения так, чтобы модель обучалась на будущем относительно тестового периода.
- **`make_future`** — создаёт временные точки будущего горизонта для прогноза. Это не прогноз `target`, а подготовка
  датасета под прогнозирование.
- **`fit_transform` / `transform` / `inverse_transform`** — применяют преобразования данных и, для обратимых
  трансформов, возвращают их к исходному представлению после прогноза.

### 1.4 Иерархия рядов

Пример: есть продажи четырёх магазинов `a`, `b`, `c`, `d`. Они объединены в две группы `X` и `Y`, а те — в общий
результат `total`.

```{image} img/01-hierarchy.png
:alt: Дерево иерархии total, группы X и Y, четыре листовых ряда a, b, c и d
```

```python
from etna.datasets import HierarchicalStructure

hs = HierarchicalStructure(level_structure={
    "total": ["X", "Y"],
    "X": ["a", "b"],
    "Y": ["c", "d"],
})

# df_raw содержит сегменты a, b, c, d
# ts_h = TSDataset(df_raw, freq="D", hierarchical_structure=hs)
```

`has_hierarchy()` проверяет наличие иерархии, `level_names()` показывает её уровни, а
`get_level_dataset(target_level="level_0")` возвращает агрегированные ряды для указанного уровня. Сумма на
верхнем уровне зависит от всех нижележащих сегментов: **прогнозы отдельных рядов и их сумма не должны противоречить
друг другу**.

### 1.5 Вспомогательные утилиты

| функция | назначение |
|---|---|
| `duplicate_data` | размножает общий признак по выбранным сегментам в `long` или `wide` |
| `set_columns_wide` | заменяет выбранные колонки/сегменты wide-таблицы значениями из другой |
| `infer_alignment` | находит для каждого сегмента дату его последнего наблюдения |
| `apply_alignment` | заменяет календарную ось относительными позициями, где конец каждого ряда — `0` |
| `make_timestamp_df_from_alignment` | переводит относительные будущие позиции обратно в даты каждого сегмента |
| `load_dataset` | загружает готовый встроенный датасет ETNA для упражнений |

**Выравнивание — не просто объединение по одной календарной оси.** Если сегменты начинаются и заканчиваются в
разные дни, иногда нужно совместить их **по возрасту истории относительно собственного конца**. Тогда последняя
точка каждого сегмента получает позицию `0`, предпоследняя — `-1` и так далее. Календарные даты при этом разные.

## 2. Практика

### Задание 1. Создаём ряды с разными свойствами

<!-- Ноутбук: раздел «Утилиты для генерации датасетов». -->

В ноутбуке генерируются постоянный, периодический, авторегрессионный ряд и ряд с заданным недельным паттерном.
Везде используем `periods=100`, `start_time="2026-09-01"`, два сегмента и воспроизводимый шум.

**Вопрос:** почему график `generate_const_df` не является горизонтальной прямой? И зачем тогда нужен этот генератор?

:::{dropdown} Ответ
`generate_const_df` задаёт **постоянную базу**, но `add_noise=True` прибавляет случайные отклонения. Ряд
колеблется около 67 без специально заложенного тренда или сезонности. Если отключить шум, получится ровная линия.
Это удобная контрольная группа: если модель «находит» в таком ряду сложную структуру, стоит проверить, не
подгоняется ли она под шум.
:::

**Вопрос:** что дают два явных шаблона `[3, 3, 3, 3, 3, 30, 3]` и `[5, 5, 5, 5, 5, 50, 5]`?

:::{dropdown} Ответ
У обоих сегментов **период семь дней**, но у второго сильнее выражен пик. При старте с 1 сентября 2026 года
(вторник) большие значения повторяются **по воскресеньям**. Это тест на способность увидеть недельный ритм,
несмотря на шум. В отличие от случайно заданного периодического узора, здесь заранее известно, в какой день
должен быть пик.
:::

**Вопрос:** как изменится характер `generate_ar_df`, если заменить `ar_coef=[0.2]` на коэффициент ближе к `1`?

:::{dropdown} Ответ
В AR(1) прошлое значение будет влиять на новое сильнее. При `0.2` отдельный скачок быстро забывается, а при
коэффициенте близком к `1` его влияние сохраняется дольше. Это **инерция**, а не заранее заданная недельная
сезонность: повторяющегося шаблона из семи значений здесь нет.
:::

### Задание 2. Переводим `long` → `wide` → `TSDataset`

<!-- Ноутбук: «Методы конвертации» и DataFrameFormat.determine. -->

Сначала получаем `df` из `generate_const_df(**PARAMS)`, затем выполняем:

```python
from etna.datasets import DataFrameFormat, TSDataset

df_wide = TSDataset.to_dataset(df)
ts = TSDataset(df, freq="D")

print(DataFrameFormat.determine(df))       # DataFrameFormat.long
print(DataFrameFormat.determine(df_wide))  # DataFrameFormat.wide
```

**Вопрос:** почему исходный `df` имеет **200 строк × 3 колонки**, а `df_wide` — **100 строк × 2 колонки**? Потеряли
ли мы половину наблюдений?

:::{dropdown} Ответ
Нет. В `long` каждое сочетание **дата × сегмент** занимает отдельную строку: `100 × 2 = 200`. В `wide`
на одну дату приходится одна строка, зато `target` каждого сегмента вынесен в отдельную колонку: **100 дат × 2
сегмента**. Это одни и те же 200 значений, только по-разному организованные. `ts.to_pandas(flatten=True)`
возвращает плоское представление.
:::

### Задание 3. Строим иерархию

<!-- Ноутбук: HierarchicalStructure, has_hierarchy, level_names, get_level_dataset. -->

Создаём четыре авторегрессионных сегмента `a`, `b`, `c`, `d` и связываем их через `X`, `Y`, `total` (схема из
раздела 1.4).

**Вопрос:** что возвращают `ts_h.has_hierarchy()`, `ts_h.level_names()` и
`ts_h.get_level_dataset(target_level="level_0")`?

:::{dropdown} Ответ
- `has_hierarchy()` → `True`: структура привязана к датасету.
- `level_names()` → `['level_0', 'level_1', 'level_2']`: есть уровень общего итога, групп и отдельных рядов.
- `get_level_dataset(target_level="level_0")` → один столбец `total`, 100 дат: значения четырёх нижних
  сегментов агрегируются на верхний уровень.

Например, в сохранённом выводе ноутбука на 1 сентября 2026 года `total = 2.842122` — сумма значений `a`, `b`,
`c`, `d` за эту дату.
:::

### Задание 4. Добавляем общий признак и подменяем данные одного сегмента

<!-- Ноутбук: duplicate_data и set_columns_wide. -->

Создаём календарный флаг `is_friday_13`: он равен `True` только 13 ноября 2026 года. Это один и тот же признак
для всех рядов, поэтому его можно вычислить один раз и размножить:

```python
from etna.datasets import duplicate_data, set_columns_wide

flags_wide = duplicate_data(
    df_flag_raw,
    segments=["segment_0", "segment_1"],
    format="wide",
)
```

**Вопрос:** почему результат `duplicate_data` содержит две колонки `is_friday_13`, хотя флаг считали один раз?

:::{dropdown} Ответ
В `wide` каждая колонка принадлежит определённому сегменту. Флаг общий по смыслу, но ETNA должна иметь
признак **для каждого сегмента отдельно**: `(segment_0, is_friday_13)` и
`(segment_1, is_friday_13)`. В сохранённом выводе — 100 дат × 2 колонки.
:::

Затем `set_columns_wide` подменяет `target` у `segment_0` значениями из `df_periodic_wide`, не трогая
`segment_1`.

**Вопрос:** как убедиться, что изменился только один сегмент?

:::{dropdown} Ответ
Сравнить одну дату до и после операции. В ноутбуке на **2026-09-01**:

| сегмент | до | после |
|---|---:|---:|
| `segment_0` | 69.483571 | 53.483571 |
| `segment_1` | 59.923146 | 59.923146 |

Изменяется выбранная пара сегмент/признак. Это не замена всего датафрейма.
:::

### Задание 5. Выравниваем ряды с разными датами окончания

<!-- Ноутбук: infer_alignment, apply_alignment, make_timestamp_df_from_alignment. -->

Генерируем три ряда, которые начинаются и заканчиваются в разное время:

| сегмент | первая дата | последняя дата | точек |
|---|---|---|---:|
| `segment_A` | 2026-09-01 | 2026-09-10 | 10 |
| `segment_B` | 2026-09-03 | 2026-09-09 | 7 |
| `segment_C` | 2026-09-05 | 2026-09-11 | 7 |

```{image} img/01-alignment.png
:alt: Три сегмента с разными датами окончания; все последние точки получают относительную позицию ноль
```

```python
from etna.datasets import infer_alignment, apply_alignment

alignment = infer_alignment(df)
df_aligned = apply_alignment(
    df, alignment, original_timestamp_name="real_date"
)
```

**Вопрос:** что означает `timestamp = 0` в `df_aligned`? Почему при одном и том же `timestamp=-6` у сегментов
могут быть разные реальные даты?

:::{dropdown} Ответ
`infer_alignment` запоминает **последнюю календарную дату отдельно для каждого сегмента**. `apply_alignment`
переносит её в позицию `0`; шесть шагов до конца становятся `-6`.

| сегмент | `timestamp=0` | `timestamp=-6` |
|---|---|---|
| `segment_A` | 2026-09-10 | 2026-09-04 |
| `segment_B` | 2026-09-09 | 2026-09-03 |
| `segment_C` | 2026-09-11 | 2026-09-05 |

Одинаковые относительные позиции — это одинаковое **расстояние до конца собственной истории**, а не одна
календарная дата. Оригинальные даты сохраняются в колонке `real_date`.
:::

**Вопрос:** какие реальные даты получатся для будущих позиций `1`, `2`, `3`?

```python
from etna.datasets import make_timestamp_df_from_alignment

future_real_dates = make_timestamp_df_from_alignment(
    alignment, start=1, periods=3, freq="D", timestamp_name="real_date"
)
```

:::{dropdown} Ответ
Каждый сегмент продолжится **от своего конца** — точно так же, как в сохранённом выводе ноутбука:

| сегмент | позиция 1 | позиция 2 | позиция 3 |
|---|---|---|---|
| `segment_A` | 2026-09-11 | 2026-09-12 | 2026-09-13 |
| `segment_B` | 2026-09-10 | 2026-09-11 | 2026-09-12 |
| `segment_C` | 2026-09-12 | 2026-09-13 | 2026-09-14 |

Это восстановление календарной сетки, **не прогноз значений `target`**.

### Задание 6. Загружаем встроенный датасет

<!-- Ноутбук: load_dataset. -->

```python
from etna.datasets import load_dataset

ts = load_dataset(name="australian_wine_sales_monthly")
ts.plot()
```

**Вопрос:** когда удобнее взять `load_dataset`, а когда — сгенерировать свой ряд?

:::{dropdown} Ответ
- **`load_dataset`** — когда хочется сразу упражняться на готовой реальной истории и сравнивать методы на одних
  и тех же данных.
- **Генератор** — когда важен контролируемый сценарий: заведомо постоянный уровень, известная
  сезонность, заданная авторегрессия или иерархия. Так проще понять, правильно ли работает метод.

В исходном ноутбуке `load_dataset` возвращает готовый `TSDataset`, который сразу можно визуализировать через
`ts.plot()`.
:::

## 3. Итоги

- **`TSDataset` — центральный объект ETNA:** он хранит временную сетку, несколько сегментов, `target` и признаки.
- **Не путать `long`, `wide` и `TSDataset`.** Это два представления `DataFrame` и отдельный объект библиотеки.
  `to_dataset`, `to_flatten`, `to_pandas` и `DataFrameFormat.determine` помогают между ними переходить.
- **Синтетика нужна для проверяемых экспериментов:** `const`, `periodic`, `ar`, `from_patterns` и `hierarchical`
  создают ряды с контролируемыми свойствами; `random_seed` фиксирует случайную составляющую.
- **Иерархия связывает ряды разных уровней.** Значения `total`, `X`, `Y` и отдельных сегментов должны согласовываться.
- **Общий календарный признак можно размножить** по сегментам через `duplicate_data`, а часть wide-таблицы заменить
  через `set_columns_wide`.
- **Выравнивание по концу истории не равно выравниванию по календарю.** У всех сегментов последняя позиция `0`,
  но реальные даты различаются; `make_timestamp_df_from_alignment` восстанавливает календарные даты будущих позиций.
