**Prophet** смотрит на временной ряд не как на цепочку «следующее значение из предыдущих», а как на кривую,
которую нужно провести через наблюдения и продолжить в будущее. Ряд раскладывается на тренд, сезонность и,
при необходимости, эффекты праздников.

Главная сильная сторона Prophet — возможность описывать **изломы тренда**: модель заранее расставляет
кандидатные точки изменения наклона и оставляет те, которые действительно нужны данным. В этой главе
разберём, как это работает, проверим разложение прогноза на компоненты и посмотрим, почему оценка на одном
тестовом окне может вводить в заблуждение. Полный код экспериментов и подготовка данных остаются в
[исходном ноутбуке](../notebooks/07-prophet-model.ipynb).

## 1. Теория

### 1.1 Идея Prophet

Prophet представляет ряд как сумму нескольких понятных компонент:

\[
y(t) = g(t) + s(t) + h(t) + \varepsilon_t,
\]

где:

- \(y(t)\) — значение ряда в момент времени \(t\);
- \(g(t)\) — тренд: кусочно-линейная функция времени, которая может менять наклон в отдельных точках;
- \(s(t)\) — сезонность: сумма периодических волн, например недельной или годовой;
- \(h(t)\) — эффекты праздников и событий, если они переданы модели;
- \(\varepsilon_t\) — шум, который модель не объясняет.

**Тренд с изломами.** В простейшем виде тренд можно записать так:

\[
g(t) =
\left(k + \sum_{j:s_j \le t}\delta_j\right)t
+
\left(m + \sum_{j:s_j \le t}\gamma_j\right),
\]

где:

- \(k\) — начальный наклон тренда;
- \(m\) — начальное смещение;
- \(s_j\) — даты-кандидаты на изломы (*changepoints*);
- \(\delta_j\) — изменение наклона в точке излома;
- \(\gamma_j\) — поправка смещения, которая сохраняет непрерывность тренда в точке излома.

После каждого излома наклон становится равен начальному наклону плюс накопленные изменения \(\delta_j\).

Ключевая особенность Prophet: модель **расставляет кандидатов в изломы заранее**, а затем штрафует их за ненужную гибкость. По умолчанию создаётся 25 кандидатов, равномерно распределённых по первым 80% обучающей истории. Изменения наклона \(\delta_j\) получают априорное распределение Лапласа с масштабом `changepoint_prior_scale`:

- маленький масштаб стягивает большинство \(\delta_j\) к нулю — тренд получается почти прямым;
- большой масштаб позволяет большему числу точек менять наклон — тренд становится гибче и может подстраиваться под локальные колебания.

**Сезонность через ряд Фурье.** Сезонная компонента задаётся суммой синусов и косинусов:

\[
s(t) =
\sum_{n=1}^{N}
\left(
a_n\cos\frac{2\pi nt}{P}
+
b_n\sin\frac{2\pi nt}{P}
\right),
\]

где:

- \(P\) — период сезонности в днях: 7 для недели, 365.25 для года;
- \(N\) — порядок ряда Фурье (`fourier_order`), то есть число гармоник;
- \(a_n\), \(b_n\) — коэффициенты, которые оцениваются моделью.

Чем больше \(N\), тем сложнее и детальнее может быть форма сезонной волны, но тем выше риск переобучения. Значения по умолчанию:

- недельная сезонность — `fourier_order=3`;
- годовая сезонность — `fourier_order=10`.

Для недельного периода три гармоники дают шесть коэффициентов — почти отдельную поправку на каждый из семи дней недели. Для годового периода десять гармоник дают двадцать коэффициентов на 365 дней: вместо 365 отдельных индексов получается гладкая кривая.

**Как модель обучается и прогнозирует.**

Параметры тренда, сезонности и праздников оцениваются совместно одной оптимизационной задачей — MAP-оценкой в Stan через `cmdstanpy`. Поэтому `fit()` здесь — полноценное обучение модели.

Прогноз на дату \(t\) — это просто значение:

\[
\hat y(t) = g(t) + s(t) + h(t).
\]

**Prophet не рекурсивен:** прогноз на десятый день не зависит от прогноза на девятый. Модель может сразу вычислить значение для любой даты в будущем. За пределами обучающей истории тренд продолжается с последним оценённым наклоном.

### 1.2 Чем Prophet отличается от предыдущих моделей

| Модель | Как строит прогноз | Как учитывает прошлое |
|---|---|---|
| `MovingAverageModel` | Среднее последних `window` значений | Рекурсивно: на дальних шагах использует собственные прогнозы. |
| `SeasonalMovingAverageModel` | Среднее значений из предыдущих сезонных циклов | Рекурсивно, с учётом `seasonality`. |
| `HoltWintersModel` | Уровень + тренд + сезонность | Рекурсивно обновляет компоненты с экспоненциальным забыванием (\(\alpha,\beta,\gamma\)). |
| `SARIMAXModel` | Авторегрессия, ошибки и сезонная часть | Использует зависимости от прошлых значений и ошибок; требует работы со стационарностью. |
| `ProphetModel` | Тренд + сезонность + эффекты событий | Подгоняет всю историю одной регрессионной моделью по времени; прогноз не рекурсивный. |

У Prophet нет авторегрессии и лагов: в модели используются функции времени. Поэтому ей не требуется
предварительная стационарность, пропуски в истории не мешают обучению, а неравномерные даты допустимы.

В отличие от `HoltWintersModel`, Prophet не обновляет сезонную волну шаг за шагом по мере поступления
наблюдений. Коэффициенты Фурье оцениваются на всей обучающей истории и затем задают одну сезонную кривую
для будущего.

### 1.3 Параметры и реализация в ETNA

В ETNA используется `ProphetModel` из `etna/models/prophet.py`. Основные параметры сгруппируем по компонентам.

**Тренд \(g(t)\):**

| Параметр | Назначение |
|---|---|
| `growth` | Тип тренда: `"linear"` — кусочно-линейный; `"flat"` — без тренда; `"logistic"` — рост с насыщением к потолку `cap`. |
| `n_changepoints` | Количество кандидатных точек излома. По умолчанию `25`. |
| `changepoint_range` | Доля обучающей истории, в которой размещаются кандидаты. По умолчанию `0.8`. |
| `changepoints` | Явный список дат изломов вместо автоматического размещения. |
| `changepoint_prior_scale` | Гибкость тренда: насколько сильно модель может менять наклон. По умолчанию `0.05`. |

Для `growth="logistic"` в данных требуется колонка `cap`, задающая верхний предел роста.

**Сезонность \(s(t)\):**

| Параметр | Назначение |
|---|---|
| `weekly_seasonality` | Включение недельной сезонности: `True`, `False`, число (`fourier_order`) или `"auto"`. |
| `yearly_seasonality` | То же для годовой сезонности. |
| `daily_seasonality` | То же для суточной сезонности. |
| `seasonality_mode` | `"additive"` — сезонная поправка складывается с трендом; `"multiplicative"` — умножает тренд на \(1+s(t)\). |
| `seasonality_prior_scale` | Сила сезонности: меньшее значение сильнее сглаживает сезонную компоненту к нулю. |
| `additional_seasonality_params` | Список дополнительных сезонностей с собственными `period` и `fourier_order`. |

В режиме `"auto"` Prophet включает:

- недельную сезонность, если в обучении есть не менее двух недель истории и частота данных выше недельной;
- годовую — если история составляет не менее 730 дней (два года);
- суточную — только если шаг данных меньше одного дня.

**Праздники и события \(h(t)\):**

- `holidays` — датафрейм с колонками `holiday`, `ds` и необязательными `lower_window` / `upper_window`;
- `holidays_prior_scale` — сила эффекта праздников.

**Дополнительные параметры:**

- `mcmc_samples=0` — точечная MAP-оценка; при значении больше нуля включается полный байесовский вывод, который работает медленнее;
- `interval_width` и `uncertainty_samples` — ширина и количество симуляций для интервалов прогноза;
- `timestamp_column` — использовать время из колонки, а не из индекса.

В ETNA обучение выполняется отдельно для каждого сегмента (`PerSegmentModelMixin`). Внутри используется
`prophet.Prophet`, а API стандартный:

```python
model.fit(train_ts)

future_ts = train_ts.make_future(future_steps=HORIZON)
forecast_ts = model.forecast(future_ts)
```

Prophet поддерживает экзогенные регрессоры: колонки `TSDataset`, объявленные как `known_future`, ETNA
передаёт в `Prophet.add_regressor()`. Колонки, значения которых неизвестны в будущем, не могут использоваться
как будущие регрессоры.

Можно запросить интервалы прогноза:

```python
forecast_ts = model.forecast(
    future_ts,
    prediction_interval=True,
    quantiles=[0.025, 0.975],
)
```

Через `model.get_model()` доступны внутренние объекты `prophet.Prophet` по сегментам. Через
`forecast(..., return_components=True)` можно получить компоненты прогноза: например,
`target_component_trend`, `target_component_weekly`, `target_component_yearly`.

**Ограничение разложения:** `return_components=True` в ETNA поддерживает только аддитивные компоненты.
Для `seasonality_mode="multiplicative"` такой вызов приводит к `ValueError`. В этом случае компоненты можно
получать через внутренний объект Prophet и его `predict()`.

### 1.4 Особенности Prophet

- **Изломы ищутся только в первых 80% истории.** При `changepoint_range=0.8` перелом тренда в последних 20%
  обучающего периода может остаться незамеченным. Модель продолжит прежний наклон. Можно увеличить
  `changepoint_range` до `0.9–0.95` или передать даты изломов явно.
- **Тренд за пределами истории продолжается последним наклоном.** На длинном горизонте прямая может уйти
  слишком высоко или слишком низко. Если выраженного направления нет, стоит проверить `growth="flat"`.
- **Нет рекурсии — нет ограничения вида `lag ≥ horizon`.** Prophet может напрямую спрогнозировать любую
  дату. Но это не означает, что прогноз на длинном горизонте автоматически надёжен: он зависит от того,
  насколько верно продолжается последний наклон и сезонный профиль.
- **Годовая сезонность требует длинной истории.** При стандартном режиме `"auto"` нужно не менее двух лет.
  На истории длиной около пяти месяцев Prophet увидит только тренд и недельную волну.
- **Сезонная волна фиксирована на всю историю.** Если амплитуда недельного паттерна со временем меняется,
  Prophet не подстраивает коэффициенты Фурье отдельно для последних недель. Это отличие от ETS, у которой
  сезонные индексы обновляются.
- **Праздники — отдельный источник сигнала.** Их можно передать модели, но в экспериментах этой главы
  праздничные эффекты не используются.

### 1.5 Перекрёстная проверка: `Pipeline.backtest`

До сих пор качество моделей оценивалось на одном тестовом окне — например, на последних 14 днях. Но это
только одна точка наблюдения: если именно эти две недели оказались необычными, вывод «модель A лучше модели B»
может оказаться случайным.

**Backtest** повторяет процесс «обучи → спрогнозируй → посчитай метрику» несколько раз, сдвигая тестовое окно
назад по истории. Так мы видим качество модели на нескольких временных отрезках.

```text
expand — расширяющееся окно              constant — скользящее окно
fold 0: [train====] [test]               fold 0: [train====] [test]
fold 1: [train========] [test]           fold 1:     [train====] [test]
fold 2: [train============] [test]       fold 2:         [train====] [test]
fold 3: [train================] [test]   fold 3:             [train====] [test]
```

- `mode="expand"` — начало train всегда одно и то же, а каждый следующий фолд добавляет историю. Это похоже
  на продовый сценарий, когда модель переобучается на всём, что накопилось.
- `mode="constant"` — длина train остаётся постоянной, а окно скользит вперёд. Такой режим полезен, если
  старая история может мешать после смены поведения ряда, или если нужно сравнить фолды при одинаковом
  количестве обучающих данных.
- Тестовые окна по умолчанию идут подряд и не пересекаются: шаг между ними (`stride`) равен `horizon`.

В ETNA 3.0.0 `backtest` вызывается у `Pipeline`, а не напрямую у модели:

```python
pipeline = Pipeline(
    model=ProphetModel(),
    transforms=[],
    horizon=HORIZON,
)

result = pipeline.backtest(
    ts=ts,                    # весь ряд, не только train
    metrics=[SMAPE()],
    n_folds=5,
    mode="expand",
)
```

В этой версии ETNA метод возвращает словарь:

| Ключ | Содержимое |
|---|---|
| `result["metrics"]` | Метрики по сегментам и фолдам. |
| `result["forecasts"]` | Список `TSDataset`, по одному прогнозу на фолд. |
| `result["fold_info"]` | Даты начала и конца train/test каждого фолда. |
| `result["pipelines"]` | Обученные конвейеры каждого фолда. |

В пособии для ETNA 2.x результат описывался как кортеж из трёх датафреймов. В ETNA 3.0.0 это уже словарь,
а прогнозы хранятся списком отдельных `TSDataset`.

Основные параметры `backtest`:

- `ts` — весь ряд, включая train и тестовые участки; фолды нарезаются внутри метода;
- `metrics` — список метрик, например `[SMAPE(), MAE()]`;
- `n_folds` — число фолдов или явный список `FoldMask`;
- `mode` — `"expand"` или `"constant"`;
- `aggregate_metrics=False` — сохранять отдельную строку на каждый фолд; `True` — агрегировать значения
  по фолдам;
- `refit=True` — переобучать модель на каждом фолде;
- `stride` — шаг между фолдами, по умолчанию равен `horizon`;
- `n_jobs` — число параллельных задач.

`plot_backtest(result["forecasts"], ts)` визуализирует прогнозы по фолдам. Если передать
`history_len="all"`, на графике будет видна вся история перед каждым тестовым окном.

## 2. Практика

### Задание 1. Синтетика: излом тренда

#### Шаг 1.1. Создаём синтетический ряд с изломом

Сравним Prophet и `HoltWintersModel` на синтетическом ряде, в котором тренд меняет направление:

- длина ряда — 126 дней (18 недель);
- до 70-го дня тренд растёт на `+2` в день;
- после 70-го дня тренд падает на `−1` в день;
- добавлены недельная сезонность и шум.

```python
import numpy as np
import pandas as pd

from etna.datasets import TSDataset
from etna.models import ProphetModel, HoltWintersModel
from etna.metrics import SMAPE
from etna.analysis import plot_forecast

DAY_OF_WEEK_PATTERN = np.array(
    [10, 20, 15, 25, 30, 50, 60],
    dtype=float,
)

def make_break_series(
    break_day=70,
    periods=126,
    slope_before=2,
    slope_after=-1,
    start_level=100,
    noise_sd=3,
    seed=42,
):
    rng = np.random.RandomState(seed)
    t = np.arange(periods)

    level_at_break = start_level + slope_before * break_day
    trend = np.where(
        t < break_day,
        start_level + slope_before * t,
        level_at_break + slope_after * (t - break_day),
    )

    seasonal = np.tile(
        DAY_OF_WEEK_PATTERN,
        periods // 7 + 1,
    )[:periods]
    noise = rng.normal(0, noise_sd, periods)

    df = pd.DataFrame({
        "timestamp": pd.date_range(
            "2026-01-01",
            periods=periods,
            freq="D",
        ),
        "segment": "synthetic",
        "target": trend + seasonal + noise,
    })

    return TSDataset(df=df, freq="D")

ts = make_break_series()
HORIZON = 14
train_ts, test_ts = ts.train_test_split(test_size=HORIZON)
```

```{image} img/07-prophet-synthetic-changepoint.png
:alt: Синтетический ряд со сменой тренда на 70-м дне, недельной сезонностью и шумом
```

Сравним две модели на одном и том же разбиении:

```python
models = {
    "ets": HoltWintersModel(
        trend="add",
        seasonal="add",
        seasonal_periods=7,
    ),
    "prophet": ProphetModel(),
}

forecasts = {}

for name, model in models.items():
    model.fit(train_ts)
    forecasts[name] = model.forecast(
        train_ts.make_future(future_steps=HORIZON)
    )

errors = {
    name: SMAPE()(y_true=test_ts, y_pred=forecast)["synthetic"]
    for name, forecast in forecasts.items()
}

pd.Series(errors, name="SMAPE").round(2)

model_prophet = models["prophet"]

plot_forecast(
    forecast_ts=forecasts,
    test_ts=test_ts,
    train_ts=train_ts,
    n_train_samples=14,
)
```

Результаты:

| Модель | SMAPE |
|---|---:|
| `HoltWintersModel` | 2.46 |
| `ProphetModel` | **1.35** |

```{image} img/07-prophet-ets-vs-prophet.png
:alt: Сравнение прогнозов Holt-Winters и Prophet на синтетическом ряде с изломом тренда
```

Prophet точнее на этом тестовом окне. Его преимущество — возможность явно оценить дату и величину изменения
наклона. ETS узнаёт об изменении тренда постепенно: сначала ошибается, затем сдвигает оценку наклона через
коэффициент сглаживания.

#### Шаг 1.2. Что будет, если излом ближе к концу train?

Сдвинем излом с 70-го на 95-й день. Обучающая часть заканчивается на 111-м дне, то есть излом уже попадает
в train, но находится близко к его концу.

Сравним стандартный Prophet с `changepoint_range=0.95`:

```python
ts_95 = make_break_series(break_day=95)

models = {
    "ets": HoltWintersModel(
        trend="add",
        seasonal="add",
        seasonal_periods=7,
    ),
    "prophet_default": ProphetModel(),
    "prophet_range_095": ProphetModel(changepoint_range=0.95),
}
```

Результаты:

| Модель | SMAPE |
|---|---:|
| `HoltWintersModel` | 2.20 |
| Prophet, `changepoint_range=0.8` | 4.33 |
| Prophet, `changepoint_range=0.95` | **0.77** |

```{image} img/07-prophet-changepoint-range.png
:alt: Сравнение Prophet с changepoint_range 0.8 и 0.95 при позднем изломе тренда
```

Причина в том, что стандартный Prophet расставляет кандидатов только в первых 80% train. При обучающей
истории до 111-го дня это примерно до 89-го дня. Излом на 95-м дне оказывается за пределами зоны поиска.
При `changepoint_range=0.95` кандидаты доходят примерно до 106-го дня, и модель может обнаружить излом.

Проверим несколько положений излома:

| День излома | Holt-Winters | Prophet, `range=0.8` | Prophet, `range=0.95` |
|---:|---:|---:|---:|
| 40 | 3.94 | 2.28 | 2.28 |
| 70 | 2.46 | 1.35 | 1.29 |
| 85 | 2.01 | 1.13 | 1.13 |
| 95 | 2.20 | 4.33 | **0.77** |
| 105 | 6.32 | 8.23 | **3.07** |
| 115 | 3.15 | 3.06 | 3.07 |

На 115-м дне излом уже находится в тестовой части. Ни одна модель не может знать о нём во время обучения.
Увеличение `changepoint_range` помогает, когда излом находится в train, но за стандартной границей 80%.

#### Шаг 1.3. Насколько гибким делать тренд?

Проверим `changepoint_prior_scale` на исходном ряде с изломом на 70-м дне:

| `changepoint_prior_scale` | SMAPE | Интерпретация |
|---:|---:|---|
| 0.001 | 24.59 | Слишком жёсткий тренд: модель почти не может менять наклон. |
| 0.05 | **1.35** | Значение по умолчанию; достаточно гибкости для обнаружения излома. |
| 0.5 | 1.38 | Очень гибкий тренд; на этой синтетике почти не лучше значения по умолчанию. |

```{image} img/07-prophet-changepoint-flexibility.png
:alt: Влияние changepoint_prior_scale на гибкость тренда Prophet
```

**Вопрос:** чем отличаются `changepoint_range` и `changepoint_prior_scale`? Почему увеличение одного параметра помогло при изломе на 95-м дне, а другого — нет?

:::{dropdown} Ответ
Это два разных механизма.

- `changepoint_range` определяет **где искать** изломы: какую долю обучающей истории покрывают кандидатные точки.
- `changepoint_prior_scale` определяет **насколько сильно разрешено менять** наклон в найденных кандидатных точках.

При изломе на 95-м дне стандартный диапазон `0.8` вообще не давал кандидатов рядом с ним. Поэтому увеличение
гибкости через `changepoint_prior_scale` само по себе не решило бы проблему: модели не из чего было выбрать
излом в нужном месте. Увеличение `changepoint_range` до `0.95` добавило кандидатов ближе к концу train.

Когда нужная точка уже попадает в зону поиска, `changepoint_prior_scale` регулирует, насколько сильно
модель может изменить наклон в этой точке.
:::

### Задание 2. Из чего собран прогноз Prophet

Prophet возвращает не только итоговый прогноз, но и отдельные компоненты. На синтетическом ряде посмотрим,
как складываются тренд и недельная сезонность.

```python
forecast_comp_ts = model_prophet.forecast(
    train_ts.make_future(future_steps=HORIZON),
    return_components=True,
)

components = forecast_comp_ts.get_target_components()["synthetic"]
components.head()
```

В нашем эксперименте Prophet автоматически включил только недельную сезонность:

```text
сезонности: ['weekly']
дней истории в train: 111
```

Годовая сезонность не включилась: обучающая история короче двух лет.

#### Шаг 2.1. Проверяем сумму компонент

```python
check_df = components.copy()
check_df["sum"] = components.sum(axis=1)
check_df["target"] = forecast_comp_ts[:, "synthetic", "target"]
check_df["diff"] = check_df["target"] - check_df["sum"]

print(f"максимальное расхождение: {check_df['diff'].abs().max():.2e}")
check_df.head()
```

Максимальное расхождение между суммой компонент и `target` равно `0.00`.

В аддитивном режиме прогноз действительно состоит из двух слагаемых:

\[
\hat y(t) = \text{trend}(t) + \text{weekly}(t).
\]

Праздничной компоненты нет, потому что праздники в модель не передавались.

#### Шаг 2.2. Сравниваем недельную волну с исходным паттерном

В синтетике недельный паттерн был задан как:

```python
DAY_OF_WEEK_PATTERN = [10, 20, 15, 25, 30, 50, 60]
```

Prophet центрирует недельную волну вокруг нуля, поэтому перед сравнением из исходного паттерна нужно
вычесть его среднее значение (`30`).

| День недели | Исходный паттерн минус среднее | Компонента `weekly` | Ошибка |
|---|---:|---:|---:|
| Четверг | −20.00 | −20.71 | −0.71 |
| Суббота | −15.00 | −15.92 | −0.92 |
| Пятница | −10.00 | −9.39 | +0.61 |
| Воскресенье | −5.00 | −4.33 | +0.67 |
| Понедельник | 0.00 | −0.72 | −0.72 |
| Вторник | 20.00 | 20.31 | +0.31 |
| Среда | 30.00 | 30.76 | +0.76 |

Средняя абсолютная ошибка — всего `0.67` заказа, сумма недельной волны — практически ноль.

Почему ряд Фурье восстановил узор так точно? Для недельного периода `fourier_order=3` даёт шесть коэффициентов
(\(a_1…a_3\) и \(b_1…b_3\)). Вместе с уровнем это семь степеней свободы на семь дней недели — достаточно,
чтобы описать любой недельный паттерн. Ошибка около 0.7 объясняется шумом в синтетике.

#### Шаг 2.3. Тренд прогноза против настоящего

На исходном синтетическом ряде после 70-го дня настоящий тренд падает на один заказ в день. Проверим наклон
компоненты `trend` у Prophet:

```python
trend_fc = components["target_component_trend"]

print(trend_fc.diff().dropna().unique())
```

Наклон прогноза — `−1.0207` заказа в день, почти совпадает с настоящим `−1`.

```{image} img/07-prophet-trend-vs-true.png
:alt: Тренд Prophet в прогнозе и настоящий кусочно-линейный тренд синтетического ряда
```

Prophet продолжает последний отрезок тренда, а не усредняет рост до излома и падение после него. Оценка
опирается на все 42 дня после излома, поэтому шум усредняется. Но если после конца train направление снова
изменится, модель не узнает об этом заранее.

#### Шаг 2.4. Нерекурсивность

Проверим, может ли Prophet спрогнозировать только одну дату — 28-й день после конца train — без расчёта
предыдущих 27 дней.

```python
prophet_raw = model_prophet.get_model()["synthetic"]

forecast_28 = model_prophet.forecast(
    train_ts.make_future(future_steps=28)
)[:, "synthetic", "target"]

day_28 = forecast_28.index[-1]

single_day = prophet_raw.predict(
    pd.DataFrame({"ds": [day_28]})
)["yhat"].iloc[0]

print(single_day, forecast_28.iloc[-1])
```

Оба значения совпали: `230.5288`.

Для сравнения построим рекурсивный прогноз `MovingAverageModel(window=7)` на те же 28 дней. На дальнем
горизонте он начинает усреднять собственные прогнозы, из-за чего тренд и недельные колебания затухают.

```{image} img/07-prophet-direct-vs-recursive.png
:alt: Сравнение нерекурсивного прогноза Prophet и рекурсивного MovingAverageModel на 28 дней
```

В последние семь дней прогноза `MovingAverageModel` почти выродился в горизонтальную линию около `238.35`,
тогда как Prophet сохранил тренд и недельную волну.

**Вопрос:** почему Prophet может сразу спрогнозировать 28-й день, а `MovingAverageModel` — нет? Что происходит
с дальним прогнозом рекурсивной модели?

:::{dropdown} Ответ
Prophet вычисляет значение на конкретную дату напрямую: подставляет её в функции тренда и сезонности.
Ему не нужны промежуточные прогнозы.

`MovingAverageModel` строит следующий шаг на основе последних семи значений. Когда фактические наблюдения
заканчиваются, в это окно постепенно попадают собственные прогнозы модели. Колебания усредняются, а тренд
затухает — поэтому дальний прогноз становится почти постоянным.

У Prophet нет такого накопления рекурсивной ошибки, но есть другое ограничение: если последний наклон тренда
не сохранится в будущем, прогноз будет систематически уходить от факта.
:::

#### Шаг 3.3. Агрегированные метрики

Если вызвать `backtest` с `aggregate_metrics=True`, вместо отдельной строки на каждый фолд останется одна
строка на сегмент. В нашем эксперименте:

```text
aggregate_metrics=True:      3.4273
среднее SMAPE по 4 фолдам:   3.4273
разброс по фолдам: от 0.90 до 7.36, std = 2.98
```

Среднее удобно для сравнения моделей, но оно скрывает разброс между окнами. За одним числом `3.43` стоят
как почти идеальные фолды, так и фолд с ошибкой `7.36`.

**Вопрос:** почему одного holdout недостаточно для выбора модели, даже если его тестовый период совпадает
с последним фолдом backtest?

:::{dropdown} Ответ
Последний фолд действительно совпадает с обычным holdout. Но он использует больше всего обучающей истории
и в этом эксперименте оказался одним из удачных окон.

На более ранних фолдах модель сталкивается с другими состояниями ряда: например, с моментом самого излома
или с периодом, когда излом уже произошёл, но ещё не попал в зону поиска changepoints.

Backtest показывает не только среднее качество, но и устойчивость к разным положениям тестового окна.
Поэтому при сравнении моделей нужно смотреть и агрегированную метрику, и отдельные ошибки по фолдам.
:::

#### Шаг 4.1. Формулируем гипотезу до обучения

По графикам из предыдущей главы про Holt-Winters видно, что у этих рядов почти нет выраженного тренда,
но есть сильная недельная сезонность. Проверим это численно:

| `a6dffdeb` | 323.80 | −0.17 | −22.79 | 171.65 | Saturday | Monday |

Из этого следуют гипотезы:

1. **Тренд слабый.** Можно проверить `growth="flat"` или жёсткий тренд с маленьким

2. **Недельная сезонность сильная.** Prophet включит её автоматически; при стандартных настройках

3. **Годовой сезонности не будет.** 139 дней истории недостаточно для автоматического включения годовой

4. **Аддитивный и мультипликативный режимы стоит сравнить.** При почти постоянном уровне разница может быть
   небольшой.
5. **Есть риск для юнита `a6dffdeb`.** У него недельная волна со временем сужалась. Holt-Winters мог
   подстраивать сезонные индексы, а Prophet использует одну сезонную волну на всю историю. Поэтому он может
   прогнозировать среднюю ширину недельной «пилы», а не её последнее состояние.

За 14 дней уровень снижается всего на 2–3 заказа при среднем уровне около 280–320. Основная форма прогноза
— уровень плюс недельная волна:

- у `70650540` недельная компонента колеблется примерно от `−47` до `+67` заказов;
- у `a6dffdeb` — примерно от `−65` до `+106` заказов.

потому, что модель продолжает небольшой спад последних недель.

#### Шаг 4.4. Проверяем вывод на пяти окнах backtest

Теперь сравним пять конфигураций Prophet с лучшей конфигурацией `HoltWintersModel` на пяти последовательных
окнах. Для каждого фолда модель обучается заново на доступной истории.

```python
# Создаём новые экземпляры: модели из prophet_configs уже обучены на holdout.
backtest_models = {
    "default": ProphetModel(),
    "flat": ProphetModel(growth="flat"),
    "mult": ProphetModel(seasonality_mode="multiplicative"),
    "cps_0.5": ProphetModel(changepoint_prior_scale=0.5),
    "cps_0.005": ProphetModel(changepoint_prior_scale=0.005),
    "holt_winters": HoltWintersModel(
        trend=None,
        seasonal="add",
        seasonal_periods=7,
    ),
}

backtest_results = {}
for name, model in backtest_models.items():
    backtest_results[name] = Pipeline(
        model=model,
        transforms=[],
        horizon=HORIZON,
    ).backtest(
        ts=units_ts,
        metrics=[SMAPE()],
        n_folds=5,
        mode="expand",
    )
```

|---|---:|---:|---:|---:|---:|
| `HoltWintersModel` | **7.77** | **8.90** | 1.63 | 7.51…11.19 | 2 |
| Prophet `flat` | 9.22 | **9.16** | 1.57 | 7.00…11.19 | 2 |
| Prophet `mult` | 9.23 | 9.47 | 1.08 | 7.92…10.75 | 0 |
| Prophet `default` | 9.09 | 9.66 | 1.11 | 8.11…10.85 | 1 |
| Prophet `cps_0.5` | 9.18 | 9.86 | 1.34 | 8.45…12.01 | 0 |
| Prophet `cps_0.005` | 9.81 | 10.54 | 1.91 | 8.13…13.41 | 0 |

Порядок моделей на holdout не сохранился. Среди конфигураций Prophet `default` была лучшей на последнем
окне, но по среднему за пять фолдов первой стала `flat`.

Разброс между фолдами одной модели заметно больше разницы между средними значениями Prophet-конфигураций:
стандартное отклонение составляет `1.08–1.91`, тогда как средние отличаются на несколько десятых пункта.

`HoltWintersModel` оказался лучшим по среднему SMAPE (`8.90` против `9.16` у лучшего Prophet `flat`), но
разница меньше одного стандартного отклонения. Поэтому устойчивый вывод здесь не в том, что ETS значительно
лучше Prophet, а в том, что на этих рядах ETS не уступает ему.

**Вопрос:** можно ли выбирать между моделями по одному 14-дневному holdout, если разница в SMAPE составляет
0.5–1 пункт?

:::{dropdown} Ответ
Нет. В этом эксперименте holdout выбрал бы `HoltWintersModel` как явного лидера (`7.77`), а среди Prophet —
`default` (`9.09`). Но по пяти окнам лучшей конфигурацией Prophet стала `flat`, а средний результат
`HoltWintersModel` оказался `8.90`.

Стандартное отклонение SMAPE по фолдам одной модели составляет примерно `1.1–1.9` пункта — больше разницы
между средними Prophet-конфигураций. Поэтому одно тестовое окно не даёт надёжного основания выбирать между
моделями с такой небольшой разницей. Для сравнения нужно смотреть несколько окон и проверять разброс
ошибки по ним.
:::

## 3. Итоги

- **Prophet раскладывает ряд на тренд, сезонность и эффекты событий.** Тренд может менять наклон в точках
  `changepoint`, а сезонность описывается рядом Фурье.
- **`changepoint_range` и `changepoint_prior_scale` отвечают за разные вещи.** Первый параметр задаёт,
  где искать изломы, второй — насколько сильно разрешено менять наклон.
- **Prophet не рекурсивен.** Прогноз на конкретную дату можно получить напрямую; промежуточные прогнозы
  не нужны. Поэтому недельная структура не затухает на длинном горизонте так, как у рекурсивного
  скользящего среднего.
- **Тренд за пределами истории продолжается последним наклоном.** Если поведение ряда снова изменится,
  модель не узнает об этом до появления новых наблюдений.
- **Сезонность Prophet фиксирована на всю обучающую историю.** Если недельный профиль со временем меняется,
  модель прогнозирует одну усреднённую волну, а не адаптирует её к последним неделям.
- **На синтетике Prophet хорошо обнаружил излом**, если тот попадал в зону поиска changepoints. При изломе
  на 95-м дне стандартный `changepoint_range=0.8` пропустил его, а `0.95` снизил SMAPE с `4.33` до `0.77`.
- **Backtest показывает то, чего не видно на одном holdout.** На синтетике SMAPE Prophet менялся от `0.90`
  до `7.36` в зависимости от положения тестового окна и доступной информации об изломе.
- **На двух реальных юнитах лучшая Prophet-конфигурация по holdout — `default`, а по пяти фолдам — `flat`.**
  Это ещё раз показывает, что один holdout может давать случайное преимущество.
- **На исследованных реальных рядах Holt-Winters не уступил Prophet.** Его средний SMAPE за пять фолдов —
  `8.90`, у лучшего Prophet — `9.16`; разница невелика относительно разброса по окнам.
- **Главный методический вывод:** при выборе модели не ограничиваться одним тестовым периодом. Сравнивать
  среднее качество на нескольких временных окнах и обязательно смотреть на разброс ошибки между фолдами.
